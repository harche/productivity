# Twitter/X CLI

Read and interact with Twitter/X using the user's Chrome session. Auth tokens are extracted directly from Chrome's cookie store — no browser automation or API keys required.

## Prerequisite

The user must be logged into X (twitter.com) in Google Chrome. The tool reads the `auth_token` and `ct0` cookies directly from Chrome's storage files on disk.

If Chrome extraction fails (e.g., different browser, locked DB), the tool automatically falls back to Playwright browser injection. For the fallback, X must be open in Chrome and connected via `playwright-cli open --extension`.

On first use, the tool discovers Twitter's GraphQL query IDs from the site's JS bundles and caches them (~24h TTL). Run `discover` to refresh manually if API calls start failing.

## Commands

All commands go through a single CLI tool bundled at `${CLAUDE_PLUGIN_ROOT}/twitter-browser-tools/twitter.mjs`.

```bash
# Verify auth and show current user
node ${CLAUDE_PLUGIN_ROOT}/twitter-browser-tools/twitter.mjs init

# Fetch content from a Twitter/X URL (tweets, profiles, search)
node ${CLAUDE_PLUGIN_ROOT}/twitter-browser-tools/twitter.mjs url "<twitter-url>"

# Get a single tweet
node ${CLAUDE_PLUGIN_ROOT}/twitter-browser-tools/twitter.mjs tweet <tweetId>

# Get tweet with full conversation thread
node ${CLAUDE_PLUGIN_ROOT}/twitter-browser-tools/twitter.mjs thread <tweetId>

# Get user profile
node ${CLAUDE_PLUGIN_ROOT}/twitter-browser-tools/twitter.mjs user <username>

# Get user's tweets
node ${CLAUDE_PLUGIN_ROOT}/twitter-browser-tools/twitter.mjs user-tweets <username> [count]

# Search tweets (may require Playwright — see Search section below)
node ${CLAUDE_PLUGIN_ROOT}/twitter-browser-tools/twitter.mjs search "<query>" [count]

# Home timeline
node ${CLAUDE_PLUGIN_ROOT}/twitter-browser-tools/twitter.mjs timeline [count]

# Post a tweet (ALWAYS confirm with user first)
node ${CLAUDE_PLUGIN_ROOT}/twitter-browser-tools/twitter.mjs post "<text>"

# Reply to a tweet (ALWAYS confirm with user first)
node ${CLAUDE_PLUGIN_ROOT}/twitter-browser-tools/twitter.mjs reply <tweetId> "<text>"

# Like a tweet (ALWAYS confirm with user first)
node ${CLAUDE_PLUGIN_ROOT}/twitter-browser-tools/twitter.mjs like <tweetId>

# Retweet (ALWAYS confirm with user first)
node ${CLAUDE_PLUGIN_ROOT}/twitter-browser-tools/twitter.mjs retweet <tweetId>

# List bookmarks
node ${CLAUDE_PLUGIN_ROOT}/twitter-browser-tools/twitter.mjs bookmarks [count]

# Refresh GraphQL query IDs from Twitter's JS bundles
node ${CLAUDE_PLUGIN_ROOT}/twitter-browser-tools/twitter.mjs discover
```

## URL Parsing

When the user shares a Twitter/X URL, use the `url` command — it automatically detects the content type and fetches it:

```bash
node ${CLAUDE_PLUGIN_ROOT}/twitter-browser-tools/twitter.mjs url "https://x.com/naval/status/1002103360646823936"
```

Supported URL patterns:
- `x.com/<user>/status/<id>` or `twitter.com/<user>/status/<id>` — tweet with thread
- `x.com/<user>` or `twitter.com/<user>` — user profile
- `x.com/search?q=<query>` — search results
- `x.com/home` — home timeline
- `x.com/i/bookmarks` — bookmarks

## Search Restrictions

Twitter's SearchTimeline endpoint requires a `x-client-transaction-id` header that is cryptographically generated by the browser's JavaScript. Direct API calls (Chrome backend) will be blocked with an empty 404.

The CLI handles this automatically:
1. Tries the direct API first
2. If blocked, falls back to **Playwright navigation** — opens the search URL in the browser and captures the API response

For search to work reliably, ensure `playwright-cli open --extension` is connected to your Chrome session.

## Output Format

All commands output **clean JSON** with:
- Expanded t.co URLs replaced with original URLs
- Media URLs shown separately from tweet text
- Engagement metrics (likes, retweets, replies, quotes, views)
- Author info (handle, display name)
- Quoted tweet content inlined

## Error Handling

- If Chrome extraction fails, the tool falls back to Playwright automatically
- If both Chrome and Playwright fail, you'll get a clear error about what's needed
- Rate limiting (429) is handled automatically with retry
- 800-1500ms random delay between API calls to mimic human patterns
- If GraphQL query IDs become stale, run the `discover` command to refresh

## Important

- **Always confirm with the user before posting tweets, replying, liking, or retweeting.**
- All actions happen as the logged-in Chrome user.
- Auth tokens are extracted from Chrome's encrypted Cookies database. Falls back to Playwright if needed.
